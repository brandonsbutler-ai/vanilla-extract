# push-guard allowlist -- goes at .githooks/push-guard-allow.txt
#
# THREE tab-separated fields, ALL of which must match before a finding is
# suppressed:
#
#     <rule-id>  <path-glob>  <exact matched text | /regex/ | sha256:HEX>
#
# All three are required on purpose. One field would let a single line switch
# a whole category off, which is how allowlists quietly turn a gate into
# decoration. As written, an entry exempts one known string in one known file:
# a NEW C:\ path appearing in README.md still blocks.
#
# Use sha256:<hex> for anything you must exempt without writing it down --
# the guard prints that form for you on any credential finding.
#
# The guard never scans this file's own contents. That is a deliberate trust
# boundary: it has to quote the strings it exempts. Review changes to it the
# way you would review a change to the hook itself.

# --- packaging/install-launcher.sh ----------------------------------------
# Portable shell. `$USER` is a variable, not this machine's account name, and
# the trailing * is a glob. This is the correct way to find removable media.
#
# INERT as of 2026-09-20: machine.media_mount's `user` group excludes the
# double-quote character, so `/media/"${USER:-}"/*` produces no finding at all
# and there is nothing here to suppress. Kept deliberately -- if that character
# class is ever widened, these two lines are what stops the widening from
# blocking a correct installer. Verified against packaging/install-launcher.sh
# line 124, which still contains exactly this text.
machine.media_mount	packaging/install-launcher.sh	/media/"${USER:-}"/
machine.media_mount	packaging/install-launcher.sh	/run/media/"${USER:-}"/
